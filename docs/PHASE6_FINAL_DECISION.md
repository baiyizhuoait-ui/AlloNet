## 3. Level 逐级对账（为什么不是 L2 / 不是 L3 / 不是 L4）

### 3.1 不是 Level 1/2
Level 2 的定义是「发现了 task-specific bottleneck，但不足以成为模型主张」，其**触发条件**是「F1/F2 不通过」。本轮 F1、F2 均通过（且 F5/F6/F7 也通过），**证据严格多于** Level 2 那一格。

### 3.2 不是 Level 3
Level 3 要求 **F1 ∧ F2 ∧ F4**。**F4 失败**：
- R3_min（lean + 1/4 **h8**）`lane_mIoU = 0.4959 < 0.5865`。
- 失败原因是**确定性死格**，不是算力不足：两个不同主干（lean / uniform）给出**相同到 4 位**的坍缩读数（0.4959 / fg 0.0），且 `lane_pixel_acc = 0.9917` 与 `mIoU = (0.9917+0)/2` 自洽（全背景预测签名）；评估器 `missing=0 unexpected=0`，权重完整。
- 唯一共同变量是 **`lane_hidden = 8`**；h16 / h32 都正常。
- ⇒ **预注册预测 P2（「最小算力破天花板 = 0 或负」）被证伪。** 修复的正下界 = **+5.54% FLOPs**（h16 无 lateral，零训练实测）。

### 3.3 不是 Level 4
以 Level 3 为前提 ⇒ 不成立。另注：F6 通过、F8 失败；即便 Level 3 成立，Level 4 也需 Round-3 的双架构 H1 —— 该项**已成立**（SUPPORTED），故 Level 4 的唯一缺口仍是 Level 3。

**并且 Level 3/4 都必须附一条降级检查**：§7 规定「F5 通过 ⇒ 最终架构**必须**移除 lateral，否则算 Level 降级」。F5 通过（0.5923 ≥ 0.5913），但**只在 h32 上测过**；h16 上的 lateral 必要性**本轮未测**（对应臂未跑）。本文档的处置是：**如实保留 lateral 并显式声明该偏离**（理由：F5 的适用范围是 h32，不比 h16），并在正文写明「若将 F5 无差别外推，本轮判级应再降一档」。

**⇒ 决定：停止训练，转写最终文档。** 这是「停机条款的**精神**」而非其字面触发条件；本文档显式记下这个差别，以免日后被读成「按条款停机」。

- **不值**：**它不能把 F4 转为 PASS，也不能把判级提到 Level 3**，且它不改变任何对外 claim 的强度。
