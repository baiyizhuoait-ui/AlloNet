## 3. 核心科学产出（四条，均可伪证）

1. **lane 修复有正下界 —— 预注册预测 P2 被证伪。** 原预测「最小算力破天花板 = 0 或负」；实测 h16 相对 1/8 lean 增 **+8.0% FLOPs**（1.0796 → 1.1656 G）。
2. **h8 是确定性死格，不是噪声。** 三重独立证据：① 两个**不同主干**（lean / uniform）输出**相同到 4 位**的 `0.4959` + `fg 0.0`；② `pixel_acc 0.9917` 与 `(0.9917+0)/2` 自洽（全背景签名）；③ 评估加载 257 keys，`missing=0 / unexpected=0`。唯一共同变量是 **`lane_hidden = 8`**。
3. **「免费非对称分配」候选被成本模型直接证伪（零训练）。** uniform + 1/4 h16 = **1.7248G**（无 lateral）/ **1.7641G**（有），**两者都 > U 的 1.6650G** ⇒ F8 第 1 条必失败。原计划那一臂（≈2.7 GPU·h）**无需再跑**。
4. **H-36 替代律被"收紧"而非"扩张"。** EXP-13 的 2×2 显示两杠杆**正交**：lane 轴 interaction = **−0.0052 < 2σ ⇒ ADDITIVE**。⇒ 替代律**只适用于「监督 × 编码器容量」**，不能外推到其它杠杆。这比原表述更精确，因而更可辩护。

**顺带**：`F6 PASS` 给出一个干净的等预算结论；但 **无支配关系** —— U 赢检测 **+0.0404**（+8.1%，代价 params ×1.73），B 赢**每 FLOPs 利用率 +32%**（对 S 为 +41%）。

> ⚠️ **引用禁令**：形式化 Pareto 会把 `R3min` / `U⁻` 标为 non-dominated，**只因它们的 FLOPs 最低**，而它们的 lane 已退化。**这两个 cell 必须剔除**，不得作为架构候选引用。

1. **永不修改正在被链执行的脚本** —— 要改就先改主体、再从冻结快照重启。

## 6. 本机训练时间账（2026-09-13 实测）

### 6.1 本机跑 100 epoch 要多久

**实测锚点**（本机 = RTX 5060 **Laptop** 8GB + Intel Ultra 9 275HX 24 核）：

| 观测 | 值 |
|---|---|
| 每 epoch 步数 | **4366**（batch=16，`tri_train` 69,863 张） |
| 稳态步进 | **96 ms/step**（全臂均值 103.5 ms，含首步 4894 ms 暖机） |
| **每 epoch** | **≈ 7.0 min** |
| 20ep 臂实测 | **132–142 min**（×9 个臂，一致） |
| 40ep 臂实测 | **277 min** ≈ 2× ✔ 线性成立 |
| eval（10,000 图，6.5 ms/img） | **271 s ≈ 4.5 min** |
| **⇒ 100 epoch（训练+评估）** | **≈ 11.7 h** |

**瓶颈已定位**：平均 **GPU 利用率 78%**（全程 73–89%，仅一次掉到 48%），而纯 GPU 合成张量探针 b=16 只要 **68.2 ms/step** ⇒ **约 22% 的墙钟在等数据管线**。
- `num_workers` 已自动抬到 **8**（配置写 2，`train.py` 自动改，因 `cores=24`）⇒ **不是核数不够**，再抬收益有限。
- **本机理论下限 ≈ 8.25 h**（假设数据管线被完全隐藏，实际不可达）。
- 推论：**换任何更强的 GPU，收益都被数据管线压缩** —— 约 22% 的墙钟在数据侧，不随 GPU 变快，所以算力提升**无法按 FLOPs 比例兑换成墙钟**。

### 6.2 钱与决定：全部在本机跑（不租卡）

| 口径 | 值 |
|---|---|
| 本机跑 1 次 100ep（训练+评估） | **11.8 h**，电费 **¥1.3–1.6**（边际 ~190 W） |
| 本机跑 3 次（3 seeds） | **35.2 h**，可拆段 |
| 训练之外的代价 | 笔记本满载发热/噪音 11.8 h |

**为什么不租（2026-09-13 实测后定案）**：本地上行 **0.82 MB/s**（下载 10.6–12.6 MB/s）。11 GB 数据集（`data/bdd100k`）上传需 **≈3.8 h**（保守上界；境内路由乐观 1–1.5 h），加调试/装环境/sanity **2–3 h**，租卡总墙钟 **12.5–14.5 h** —— **比本机 11.8 h 更慢**，还要多花 ¥10–20 与 2–3 h 在场时间；且"租多台并行"会 ×N 倍重复上传。

## 7. 训练配置（已定：本机、`batch=16`、只加 epoch）

**不租卡**（理由见 §6.2）。本任务显存只需 **2.4 GB**（batch=16 实测峰值 2236–2468 MiB）；放大 batch 也没有摊销收益（`ms/img` 随 batch **上升**：3.94 → 4.26 → 4.46，b=64 在 8 GB 上 OOM）。

**可比性纪律（唯一选项）**：**保持 `batch=16` 只加 epoch** → 与已跑的 40ep 直接可比、不必重建基线、省显存。

⚠️ **断点续训陷阱**：`CosineAnnealingLR` 的 `T_max` 必须仍按 **100ep 的总步数**设。若按拆分后的段长设，LR 会提前落到底板，**伪造出"后面没有余量"的假结论**。

## 8. 下一步（周一截止线前）

**设计空间已搜完** —— 这不是悲观，是有证据的结论：预注册 Rule 1「无任何证据要求新增计算单元」、h8 确定性死格、U⁻ 被成本模型证伪、F10 是干净的阴性对照。**但"没有方向"只对「再训一个模型」成立。** 剩下的三条不在模型里：

| # | 方向 | 要 GPU 吗 | 价值 |
|---|---|---|---|
| **①** | **改 claim**：从「更强的架构」→「**瓶颈测量 + 按瓶颈维度分配算力的成本规则**」 | ❌ **0** | **最大，直接决定生死** |
| **②** | **协议对等**〔2026-09-15 勘误：拆成两层〕**评测口径对等 ✅ 已完成**；**训练预算对等 ❌ 未达成**（外部基线为官方权重 **≈200ep + EMA @640×384**，我方 100ep） | ✅ 少 | **消除头号拒稿理由**（30–40% → 50–65%） |

### 10.4 判决：**D-2 触发**

### 10.5 三条可写进论文的科学含义

1. **「落后」的一半是预算假象。** 40ep→100ep 把 DA 差距从 **−0.0202 削到 −0.0123**（Δ = +0.0079，**仅在我方出厂口径下**）。原先"结构性缺陷"的读法被显著削弱；**预算等价是对比成立的硬前提**。〔2026-09-15 勘误：原写"Δ = +0.0079 > 2σ"；σ 倍数修辞按裁定 C 第 3 条删除〕
2. **检测领先随预算放大，且首次显著。** +0.0245（N=1，不显著）→ **+0.0429（s0）/ +0.0407（n=3 均值）**。〔2026-09-15 勘误：原写"+0.0429（14σ）"，σ 倍数修辞删除〕原句附带的架构解释——"检测头绕过 Z 瓶颈、DA/lane 头必须穿过 z=16 瓶颈"——**对主模型 Model B 不成立**（Model B 是 **R2**，`from_z: true`，检测头**流经** Z）；该解释的原型是 Phase 3A/3B 的 **R0** 配置。**G3 出结果前，此解释不得写进论文**（见 `docs/PHASE6_G3_PREREGISTRATION.md` §0-C2）。
