## 1. 先明确一件事：我们命名的是一个**方法**，不是一个**模型**

这是整份提案的前提，也是决定名字好坏的分水岭。

| | 模型名（我们不适用） | 方法名（我们适用） |
|---|---|---|
| 例子 | YOLOP / TwinLiteNet / TriLiteNet / SC2-P | GradNorm / Uncertainty Weighting / SimOTA / ATSS |
| 语法 | 名词，暗示"一个东西" | 名词化概念，暗示"一条原理/规则" |
| 评审第一反应 | "**它比谁强？**" | "**这条原理成立吗？**" |
| 我们的胜算 | **很低**（DA 9/9 末位，见策略文档 §3） | **较高**（边际价格表 + 替代律 + 18/18 认证） |

> **命名的最实际作用，是把审稿人引到我们答得好的那个问题上。**
> 叫 `UltraLightNet` 会招来性能比较，我们必输；叫一个"价格/分配"类的方法名，
> 招来的是方法评价，我们赢。

**因此：方法名与模型实例名应当分离。** 方法名进标题与主张；模型实例沿用现有体系。

## 2. 命名红线（预注册已冻结，不得违反）

Round 4 §1 由文献碰撞检查推出，**写死**：

| 禁用词/做法 | 撞谁 |
|---|---|
| `asymmetric`（作为新颖点） | MT-TPPNet（Computers 2025）"Asymmetric Projection with Expanded-value (APEX)" |
| `channel–spatial`（作为新颖点） | MT-TPPNet "Selective Channel–Spatial Coupling (SC²)" |
| `dynamic sampling` | MDANet（IEEE TITS 2026）"Triple-Dynamic Sampling" |
| 任何 attention / 动态路由 / SE / CBAM 模块主张 | 同上 |
| "we fix (label) assignment" | YOLO26 STAL 及 DALA/RLA/IHANet/eRFOTA 一族（已工业化） |

**另外的硬约束**（来自本轮外部核查）：`marginal` / `allocation` / `budget` 这些词本身**未被占用**
（最接近的是 EMVP 的系统级 RL 调度、QBATO 的任务卸载，均为**系统层**而非**架构层**）。
⇒ 我们可以在这一组词汇里自由命名。

## 2.5 两个必须登记的概念近邻（本轮新发现，影响主张措辞）

命名核查过程中撞到两篇**同一概念家族**的工作。它们**不妨碍命名**，但**限定了我们能主张的强度**。

### (a) UIUC "边际价格"框架（arXiv:2605.01214，2026-05）

提出把"每多花一个单位的边际收益"作为 AI 系统资源分配的统一语言，并明确使用
**"价格单 (price list)" / "共同账本"** 作为类比。**与我们的核心度量同名同构。**

| | UIUC 2605.01214 | 我们 |
|---|---|---|
| 层面 | **系统层**（token / 路由 / 服务 / 训练流水线四个部门） | **架构层**（编码器容量 / 表示宽度 / 分辨率 / 监督质量） |
| 单位 | token | FLOPs |
| 产出 | 一套语言与权衡框架 | 一张**实测价格表** + 一条**替代律** + 一条分配规则 |

⇒ **影响**：
1. **正面**：说明"边际价格"不是我们生造的概念，方向有共鸣 —— 可在引言中作为框架来源引用。
2. **风险**：审稿人可能说"这不就是把已有概念搬到感知网络"。
3. **应对**：差异必须落在**具体的实测价格表（5 个架构维度）、替代律这个经验发现、
   以及等参数对照下的 B ≡ S（−28.9% FLOPs）** —— 即**经验内容**，不是框架本身。
   **主张措辞中不得出现"我们提出边际价格分配"这类框架首创式表述。**

### (b) 耿新团队 CVPR 2026《Model Merging in the Essential Subspace》

核心表述是"多任务**争同一块内部表示空间**，谁占得多谁更稳定"。**与我们的"替代律"方向相近。**

- 但该文场景是 **model merging（模型融合）**，不是多任务联合训练；
  且其表述是**定性**的。
- 这与预注册 §1 已登记的另一条同向：NMS-aware alignment (Neurocomputing 2022)
  已隐含陈述"监督强度↔表征强度"的方向性。
- ⇒ **重申红线**：我们**不得**主张"我们发现了任务间的资源竞争"（已知且已被多次陈述）。
  只能主张**定量 + 固定 params/FLOPs + 同一因子设计下双杠杆实测 + 转成分配规则**这一层。

## 3. 推荐方案

### 3.1 首选：**MARGIN**（方法名）

**读法**：/ˈmɑːdʒɪn/，一个常见英文词，审稿人一眼能读。
**对应概念**：**边际价格**（marginal price）—— 我们整篇的核心度量。
**展开**（如需缩写式）：*Marginal-price Allocation Rule for Guided Investment in Networks*

**为什么是它**
1. **一词命中核心**：我们的主张就是"每条资源维度有自己的边际价格，按价格分配而非等比扩宽"。
2. **像方法名不像模型名**：不会诱导"它比谁强"的提问。
3. **不含任何红线词**。
4. **不绑定性能声明**：3 年后"边际价格分配"这个说法仍然成立，不会因为别人刷了更高的 DA 而失效。

### 3.2 模型实例名：沿用 **Model B** / **PercepFlex-B**

**不要改。** 现有 8 张表（`phase6_final_models.csv`、`phase6_ablation.csv`、
`phase6_round4_results.csv` 等）与预注册全部使用 `Model U / S / B / U⁻` 体系，
改名会引入一整类"引用静默失效"风险（本仓库已有 7 次此类缺陷记录），收益为零。

**推荐的分工**：
- **方法/原理** → MARGIN
- **模型实例** → Model B（本次主张的形态）；U / S / U⁻ 作为对照
- **项目名** → PercepFlex（保持不变）

### 3.3 备选：**PACE**（Perception Allocation by Cost Estimation）

好念、干净、三字母 + 概念自解释。
**风险**：PACE 是跨领域高频缩写（在多个学术与工业语境中被占用），撞名概率明显高于 MARGIN。
**仅在 MARGIN 最终核查不通过时启用。**

## 4. 定义：三层写法

### 4.1 第一层 —— 一句话定义（电梯陈述）

> **PercepFlex 是一个 0.19M 参数的三任务驾驶感知网络，被当作一个工具来回答一个容量分配问题：
> 在固定参数预算下，算力应当如何在编码器与共享表示之间划分，以及这个划分如何随检测、
> 可行驶区域与车道线三个任务而不同。**

**这句话的两个关键动作**：
1. 出现 **"工具 (instrument)"** —— 我们不是在推销模型；
2. 出现 **"问题 (question)"** —— 焦点从"我们更强"转到"我们回答了什么"。

### 4.2 第二层 —— 技术定义

> 给定固定参数预算 B，我们测量每个可用资源维度（编码器容量、表示宽度、运行分辨率、
> 监督质量）在**单位 FLOPs 下的任务指标收益**——即该维度的**边际价格**——
> 然后按价格从高到低分配 B，而不是按等比扩宽（uniform scaling）分配。

### 4.3 第三层 —— 贡献定义（可声称）

| # | 可声称 | 证据来源 |
|---|---|---|
| 1 | 一张**实测的边际价格表**（5 个资源维度） | Round 4 §0 表格 |
| 2 | 一条**替代律**：监督与容量争夺同一块 headroom，**仅限编码器容量轴**（lane 轴可加，−0.0052 < 2σ） | EXP-09C / EXP-13 |
| 3 | 一条**分配规则**，其推论 **B ≡ S at −28.9% FLOPs** | F6 / F6b |
| 4 | 一个**协议认证**：18/18 发表值复现到 ±1.0（n=10,000） | Stage B |

### 4.4 必须**并列在同一段**的不可声称项

写定义时若只写 §4.3，就是选择性陈述。以下必须同段出现：

- **不支配 uniform expansion**：Model U 在检测上赢 **+0.0404**（代价 ×1.73 params）。
- **不支配任何已发表方法**：DA 在同台 9 模型中 **9/9 末位**，低于全场 22 篇中的每一个三任务模型。
- **lane 轴只有单架构支撑**（预注册 §11.1）。
- **禁止 parity / 持平措辞**（D-2 未解除，待 seeds 1–2）。

## 5. 定义的红线（不能写进去的话）

| ❌ 不能写 | 原因 |
|---|---|
| "a lightweight multi-task network achieving competitive performance" | 招来性能比较，且"competitive"与数据不符 |
| "state-of-the-art efficiency" | 没有同口径比较基准（FLOPs 口径 3.33× 不可比） |
| "an **asymmetric** architecture" | 撞 MT-TPPNet |
| "we **improve label assignment**" | 撞 YOLO26 STAL |
| "matches / is on par with published baselines" | D-2 触发中，禁令未解除 |
| "the most efficient model we evaluated" | 集合不完整（已撤回项） |

## 6. 自检清单（任何名字/定义定稿前逐条过）

1. 它暗示的是**方法**还是**性能**？→ 必须是方法。
2. 它能否在**不比较性能**的情况下被评价？→ 必须能。
3. 是否含 §2 的任一红线词？→ 必须不含。
4. 非母语审稿人能一次读出吗？→ 必须能。
5. 读完标题后，审稿人的第一个问题是不是我们答得出的那个？→ 必须是。
6. 定义段里是否**同时**包含可声称与不可声称？→ 必须同时。
