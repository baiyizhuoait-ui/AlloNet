## 为什么作废

EXP-9A 首轮（2026-09-11 10:29–10:54 训练的 A0/A1/A2 三臂）同时踩了两个
互相掩盖的仪器缺陷：

### D1 —— 评估器从未加载各臂训练权重
`evaluation/evaluate_baseline.py:build_yolop` 没有接收 checkpoint 的入口，
永远从 `weights/YOLOP_End-to-end.pth` 读发布权重。链子只传了锚框
（`YOLOP_ANCHORS_JSON`），所以三臂评估的其实是**同一个发布模型**，差别只在
解码时用的锚框。

**确诊证据**：三臂的 `lane_mIoU`（0.6038）与 `da_mIoU`（0.9115）**逐位相同**。
若真用了各自的训练权重，lane/DA 头是联合训练的，不可能四位小数完全一致。

产出（**作废**）：`phase6_round3_trained.INVALID_D1D2.csv`

| 臂 | mAP50 | 真身 |
|---|---|---|
| A0_shipped | 0.7657 | 发布模型 + shipped 锚框（≈发布基线本身） |
| A1_flip | 0.0000 | 发布模型 + flip 锚框（几何不符 → 全灭） |
| A2_kmeans | 0.0005 | 发布模型 + kmeans 锚框 |

### D2 —— 训练器与评估器输入分布不一致（且被 D1 掩盖）
数据集产出 `[0,1]` 张量；评估器对 YOLOP 再做 ImageNet 均值/方差归一化，
而训练器**不做**。于是微调把模型教成"期待未归一化输入"，评估时却给归一化
输入。

修好 D1 后才暴露 D2：200 张 val 上 A0/A1/A2 = 0.0677 / 0.0971 / 0.1049，
而发布模型是 0.7712 —— 检测能力被输入分布错配摧毁约 90%。

> ⚠️ **注意**：D2 产出的排序（A2 > A1 > A0）**恰好与 H1 预测方向一致**。
> 但它是在一个被证明"没有在测量目标变量"的仪器上产生的，且存在纯机械解释
> （kmeans 锚框数值更大，在错配单位下受害更小）。按纪律：**记录在案，
> 不作为证据。**
